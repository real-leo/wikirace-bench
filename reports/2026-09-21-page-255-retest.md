## 测试设计

本轮将 `PAGE_SHORTLIST_K` 从 64 改为 255，策略版本为 `page-target-v2-255`。
Jev、Laya MLX 使用同一浏览器观测、访问过滤、目标简介和 600 秒动作阶段预算：
候选不超过 255 时全部提供；超过 255 时全量 Score 后保留前 255（精确目标保留）。

**候选上限相同，不代表模型内部决策方式相同。**

- Jev 原生一次 Choice 支持 255 项。
- 英文 Laya 模型总输入 512 tokens；原生 255 项测试只保留 126 个选项标记，无法可靠单次处理。
  新适配器按实际 token 预算分组，最多 8 项，每组由模型选出胜者，再逐轮比较胜者。
  所有候选都进入第一轮，没有代码直接选出精确目标。只有单候选轮空时不做多余推理。
- Laya 每条 Score 的指令包含该候选完整标题，共享 state 只放目标、当前页、路径，
  不再把整批 64 个候选塞进共享 state。
- 每个实际请求的分词序列都与完整、未截断序列逐 token 比对，出现隐式截断则报错。
  长标题在 state 完整保留，选项位置提供最长 32-token 标题预览；可选描述主动缩短。
- 可选文本预算：目标说明 80 tokens，当前页说明 32，路径 40，Score context 32，Choice context 8。
  实际输入、候选映射、各轮胜者、token 审计和耗时全部保存在 trace 的 `model_calls`/`choice_rounds`。
- MLX 采用 GPU、FP16、batch size 16、512MiB allocation cache；模型预加载不计入动作时间。

部分 Jev 运行与下载或 SemIf 的 CPU 加载准备有重叠；本轮不是隔离环境的硬件吞吐基准。
不同后端的分组策略、提示格式和上下文长度仍不同，结果是系统比较，不能单独归因于模型权重。

## 适配验证

初版分组虽然保留标题，但选项位置仅写 `Link A` 等标签。在真实 Coffee 页面，
Laya 误选了 Cairo，并在后续导航中漂移。该版日志保留在 `runs/mlx-retest/smoke/`，
不纳入正式重测。

对同一候选组，把选项文字改为实际文章标题，其他状态保持不变，模型改选 Caffeine。
据此固定 `laya-mlx-page-v2-255-tournament` 适配器，再进行后续重测。

修正版 Coffee → Caffeine 浏览器检查：**1 点击成功，动作阶段 24.918s**。
本步对全部 390 个候选打分，255 项参与选择；独立日志审计验证 427 道实际问题
没有分词截断。合计 62 次本地调用（打分 25 次 + 选择 37 次）。

## 路径与审计

DNA 路径：DNA → Animal → Equestrianism → Polo → Manipuri pony。

Music 路径：Music → Music (disambiguation) → Musical notation → Musical composition →
Music theory → The Oxford Companion to Music → Oxford Companions → Sport →
Sport of athletics → AAA Championships → 2001 AAA Championships。

WWII 路径：World War II → United States → Michigan → List of Michigan state parks → Bald Mountain Recreation Area。

相比旧 64 项短名单的 Music 六跳，新 255 项这次绕路更多；不能据一次试验得出候选数量越多越好。

Laya 的 Music 路径从西方世界、欧洲转入战争、法律、英国历史，最后到达细菌相关页面；
WWII 路径长期停留在战争、军队与武器相关页面，还曾绕到考古学，没有找到目标公园。
完整路径在摘要 JSON 中，逐次请求保存在本地 `runs/mlx-retest/laya-255-articles/`。

| Laya 任务 | 实际本地 predict 调用 | 完整保留的问题输入 | 最大输入 tokens |
|---|---:|---:|---:|
| DNA | 1,492 | 9,149 | 506 |
| Music | 1,520 | 11,484 | 490 |
| WWII | 1,474 | 9,693 | 512 |

共审计 **4,486 次本地调用、30,326 道问题输入**，没有隐式截断。
审计还逐项核对了实际提交的完整标题、候选 ID、每轮分组与胜者、最终点击合法性。
完整返回的 Score 批次和 Choice 阶段均满足候选覆盖要求；DNA 最后中断的 Score 阶段中，
已完成的 2 次调用、32 道问题也通过输入审计，但不计为整个页面打分已完成。
摘要中的阶段耗时只累计已经返回的阶段；原始 trace 保留超时和部分请求证据。
本地 predict 调用数不可直接当作远程 API 请求数或图上的跳数。

### DNA 首步诊断

两边起始页面完全一致：457 个页面链接，过滤后 456 个候选，均先全量打分再选 255。
Jev 将 `Animal` 排第 9，随后选择它并在四跳内成功。
Laya 将 `Animal` 排第 429，因此它没有进入短名单；最终选择 `Biochemistry`。
Laya 后续主要沿生命科学、科技史与印度历史导航，600 秒内未找到目标。

这说明本次失败已经包含打分阶段的路径判断问题，不能仅解释为分组 Choice 的影响。
也不能据此认定模型权重是唯一原因：上下文压缩、不同提示格式和分组选择仍是比较限制。

## SemIf 下载与复现

代码：`third_party/SemIf/`，固定提交 `ca3ba65f142967030ecb453346e94d6f476a69df`。
独立环境：`.venv-semif/`，依赖见 `requirements-semif.lock.txt`。
模型：`models/Qwen3.5-4B/`，来源 `Qwen/Qwen3.5-4B`，revision
`851bf6e806efd8d0a36b00ddf55e13ccb7b8cd0a`，远端 14 个文件合计 9,342,907,469 bytes。

通过 `127.0.0.1:7890` 代理下载。一个大分片的连接明显变慢，改为校验 HTTP Content-Range
的分段续传，合并后核对完整 SHA-256。代码、环境和模型均在 Git 忽略目录中。

SemIf 当前 `core.py` 接口限制为 **2–16 个选项**，不是原生 255 项。
本次仅部署并验证其独立推理，尚未接入 WikiRace。

文件校验已完成，见 [`2026-09-21-semif-download.json`](2026-09-21-semif-download.json)。
首次原生 CLI 加载在 `mx.eval(model.parameters())` 报 Metal GPU Timeout；
失败日志保留在 `runs/mlx-retest/semif-smoke.log`。
`scripts/probe_semif_mlx.py` 只把初始权重物化放到 CPU，再用原生 GPU scorer，
已验证成功。模型、精度、sanitize、提示及评分实现未改动，加载方式写入输出 metadata。
GPU 测试与 Laya 串行。

- 加载（含源文件哈希）：130.274s。
- 三个示例均符合预期：部署成功 `yes`，忘记密码 `account_access`，只列文件名 `not_required`。
- 首次推理 5.499s；后两个短请求 0.345s、0.333s。不同请求，不能作为重复试验的中位数。
- 峰值 MLX allocation：8262.73MiB，非进程 RSS。
- 详见 [`2026-09-21-semif-smoke.json`](2026-09-21-semif-smoke.json)。仅部署烟测，不是 WikiRace 或通用准确率评测。

```bash

  --brain jev --out-dir runs/jev-255-another-run --timeout 600
```
